# Инструкции для репозитория k-skill

Этот репозиторий наследует общие правила `oh-my-codex` из родительского окружения.
Ниже перечислены правила уровня репозитория, которые действуют для всего содержимого этого каталога.

## Правила автоматизации выпусков

- Пакеты Node.js лежат в `packages/*` и используют `npm workspaces`.
- Для выпусков пакетов Node.js используется **Changesets**. Не правьте версии вручную только ради выпуска; вместо этого добавляйте файл `.changeset/*.md`.
- Публикация в npm автоматизирована через GitHub Actions и должна происходить только после слияния сгенерированного ботом запроса на слияние **«Версии пакетов» (Version Packages)** в `main`.
- Пакеты Python лежат в `python-packages/*` и используют **release-please**. Пока реального пакета Python нет, процесс выпуска Python остаётся только каркасной заготовкой.
- Публикация в PyPI должна запускаться только когда `release-please` сообщает `release_created=true` для конкретного пути пакета.
- Предпочитайте доверенную публикацию через OIDC для npm и PyPI. Не добавляйте долгоживущие маркеры реестра, если доверенная публикация доступна.

## Правила проверки

- Для выпускных изменений и изменений упаковки запускайте `npm run ci`.
- Документацию выпусков, файлы автоматизации и метаданные пакетов держите синхронными в рамках одного изменения.

## Правила установки навыков для разработки

- При тестировании или разработке навыков из этого репозитория сначала устанавливайте или синхронизируйте текущие директории навыков в глобальные каталоги навыков домашней директории пользователя.
- Используйте `~/.claude/skills/<skill-name>` для Claude Code и `~/.agents/skills/<skill-name>` для совместимых с `agents` сценариев домашней установки.
- При синхронизации `~/.agents/skills` учитывайте существующую домашнюю индирекцию, например символическую ссылку.
- Не создавайте локальные каталоги репозитория `.claude` или `.agents` для установки навыков, если пользователь явно не попросил локальный тестовый эталон внутри репозитория.

## Политика посредника для бесплатных API

- Встроенный `k-skill-proxy` предназначен только для **бесплатных API**.
- Базовая позиция: публичная конечная точка только для чтения, **без авторизации посредника по умолчанию**.
- Интерфейсы посредника для бесплатных API должны оставаться узкими, ограниченными списком разрешённых маршрутов, с буферизацией и ограничением частоты запросов.
- Если позже появятся злоупотребления или операционные проблемы, ужесточайте ограничения тогда, а не вводите обязательную авторизацию заранее.
