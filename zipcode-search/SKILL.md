# Поиск почтового индекса

## Что делает навык

Запрашивает официальную страницу поиска дорог Почтовой службы Кореи и быстро находит почтовый индекс по ключевым словам адреса.

## Граничное примечание

Этот навык остаётся на `legacy-only` границе. Русскоязычный сценарий только для чтения по индексам и адресам уже покрывается `postcalc-postcodes`, поэтому `zipcode-search` поддерживается только для обратной совместимости и не рассматривается как новый целевой перечень почтовых задач.

## Когда использовать

- «Какой почтовый индекс у этого адреса?»
- «Найди почтовый индекс для Седжондаэро 209»
- «Быстро скажи код адреса Пангёёкро 235»

## Предварительные условия

- Подключение к интернету
- `curl`
- Опционально: `python3`

## Входные данные

- Ключевые слова адреса
  - Название дороги + номер здания
  - Город/уезд/район + название дороги
  - Район/ри + земельный номер

## Рабочий процесс

### 1. Сначала запросить официальную страницу ePost

Не обходить через неофициальный поиск по картам или блоговые адресные данные, а сначала запросить официальную страницу поиска Почтовой службы:

```text
https://parcel.epost.go.kr/parcel/comm/zipcode/comm_newzipcd_list.jsp
```

Запрос работает даже с одним параметром `keyword`.

### 2. Получить HTML через curl и извлечь строки-кандидаты

Текущий эндпоинт ePost может периодически сбрасывать соединение или таймаутиться, поэтому в базовом примере используется `curl --http1.1 --tls-max 1.2` с повторными попытками вместо стандартного `urllib` Python.

```bash
python3 - <<'PY'
import html
import re
import subprocess

query = "세종대로 209"
cmd = [
    "curl",
    "--http1.1",
    "--tls-max",
    "1.2",
    "--silent",
    "--show-error",
    "--location",
    "--retry",
    "3",
    "--retry-all-errors",
    "--retry-delay",
    "1",
    "--max-time",
    "20",
    "--get",
    "--data-urlencode",
    f"keyword={query}",
    "https://parcel.epost.go.kr/parcel/comm/zipcode/comm_newzipcd_list.jsp",
]
result = subprocess.run(
    cmd,
    check=True,
    capture_output=True,
    text=True,
    encoding="utf-8",
)
page = result.stdout

matches = re.findall(
    r'name="sch_zipcode"\s+value="([^"]+)".*?name="sch_address1"\s+value="([^"]+)".*?name="sch_bdNm"\s+value="([^"]*)"',
    page,
    re.S,
)

if not matches:
    raise SystemExit("Результаты поиска не найдены.")

for zip_code, address, building in matches[:5]:
    suffix = f" ({building})" if building else ""
    print(f"{zip_code}\t{html.unescape(address)}{suffix}")
PY
```

Ключевые поля: `sch_zipcode` (почтовый индекс), `sch_address1` (основной адрес), `sch_bdNm` (название здания).

Не добавлять внешний Python-тайм-аут, а контролировать время передачи через ограничения самого `curl` (`--max-time` + повторные попытки). При ошибке передачи не сразу переходить к другому источнику, а сначала повторить с теми же параметрами повторных попыток, затем уточнить ключевое слово. На практике сначала вводите короткое название дороги + номер здания (например, `세종대로 209`), а при неудаче — полный адрес с городом/районом (например, `서울 종로구 세종대로 209`).

### 3. Нормализовать для человека

Ответ приходит в raw HTML, поэтому не вставлять его как есть, а оформить:

- Почтовый индекс
- Стандартный адрес
- Название здания, если есть
- Если кандидатов несколько, показать 3–5 верхних и указать, какой наиболее подходящий

### 4. Повторить с более точными и полными ключевыми словами при необходимости

Если результаты поиска отсутствуют или повторяются таймауты/сбросы, повторить в следующем порядке:

- Короткое название дороги + номер здания: `세종대로 209`
- Полный адрес с городом/районом: `서울 종로구 세종대로 209`
- Район/ри + земельный номер или альтернативное написание: `세종로 209`

### 5. Предпочитать временные файлы в обёрнутых оболочках

В CLI-обёртках или агентских оболочках here-doc + Python one-liner могут сломаться, поэтому на практике предпочтительнее сохранять HTML во временный файл через `mktemp` и парсить этот файл. Если добавить `| head` для частичного просмотра ответа, нисходящий поток может закрыться первым и появится `curl: (23)` — в этом случае тоже сохранять полный ответ во временный файл.

## Критерии завершения

- Найден хотя бы один кандидат с почтовым индексом
- При нескольких кандидатах видны различия в адресах для выбора пользователем
- При отсутствии результатов предложено направление для повторного поиска

## Возможные ошибки

- Изменение разметки страницы поиска Почтовой службы может сломать правило извлечения `sch_zipcode`
- Слишком широкое ключевое слово адреса может вернуть избыточно много результатов
- Единичный вызов без повторных попыток может привести к временной ошибке таймаута/сброса
- Прямое подключение через `urllib` без `curl` может привести к сбросу соединения

## Примечания

- Это навык запроса справочной информации
- Относительные даты и концепция реального времени отсутствуют, поэтому фокус на очистке строк адреса
