# Гайд по поиску почтового индекса

## Граничное примечание

Этот сценарий остаётся `устаревший без развития`: для российских сценариев только для чтения по индексам и отделениям уже есть `postcalc-postcodes`, а корейский ePost-сценарий сохраняется только ради обратной совместимости. `zipcode-search` не должен выглядеть как скрытый перечень задач на новый российский почтовый навык поверх другого источника.

## Что делает навык

- Искать официальный почтовый индекс по адресу через ePost.
- Сравнивать верхние кандидаты, если по одной улице или зданию приходит несколько строк.
- Быстро корректировать поисковую фразу, если результатов нет.

## Предварительные условия

- Доступ в интернет
- `curl`
- Необязательно: `python3`

## Входные данные

- Адресный запрос
  - Например: `세종대로 209`
  - Например: `판교역로 235`

## Рабочий процесс

1. Сначала обращаться к официальному поиску ePost, а не к неофициальным картам или блогам.
2. Передавать адрес в параметр `keyword` и получать HTML-страницу.
3. Извлекать из ответа `sch_zipcode`, `sch_address1` и `sch_bdNm`.
4. Если есть несколько кандидатов, показывать только верхние 3-5 строк.
5. Если соединение рвётся или истекает тайм-аут, повторить запрос с теми же параметрами curl повторных попыток; затем при необходимости уточнять запрос от короткого названия улицы + номер дома к полному адресу с городом/районом.

## Пример

```bash
python3 - <<'PY'
import html
import re
import subprocess

query = "세종대로 209"
cmd = [
    "curl",
    "--http1.1",
    "--tls-max",
    "1.2",
    "--silent",
    "--show-error",
    "--location",
    "--retry",
    "3",
    "--retry-all-errors",
    "--retry-delay",
    "1",
    "--max-time",
    "20",
    "--get",
    "--data-urlencode",
    f"keyword={query}",
    "https://parcel.epost.go.kr/parcel/comm/zipcode/comm_newzipcd_list.jsp",
]
result = subprocess.run(
    cmd,
    check=True,
    capture_output=True,
    text=True,
    encoding="utf-8",
)
page = result.stdout

matches = re.findall(
    r'name="sch_zipcode"\s+value="([^"]+)".*?name="sch_address1"\s+value="([^"]+)".*?name="sch_bdNm"\s+value="([^"]*)"',
    page,
    re.S,
)

if not matches:
    raise SystemExit("Результаты не найдены.")

for zip_code, address, building in matches[:5]:
    suffix = f" ({building})" if building else ""
    print(f"{zip_code}\t{html.unescape(address)}{suffix}")
PY
```

## Практические советы

- В shell-обвязке или агентной среде безопаснее сначала сохранить HTML во временный файл: `mktemp`.
- Если делать `curl ... | head`, можно спровоцировать `curl: (23)` из-за преждевременного закрытия нисходящего потока; лучше писать полный ответ во временный файл.
- Обычно лучше уточнять запрос в таком порядке: короткое название улицы + номер дома -> полный адрес с городом/районом -> запись по кварталу или участку.

## Ограничения протокола и клиента

Ограничения протокола и клиента остаются теми же и после русификации.

- У текущего ePost эндпоинта нативный `urllib` иногда ломается на TLS/HTTP negotiation и получает reset.
- Даже с `curl` возможны редкие тайм-аут/сброс, поэтому базовый пример включает `--retry 3 --retry-all-errors --retry-delay 1`.
- В документации рекомендуется путь `curl --http1.1 --tls-max 1.2`, а Python используется только для парсинга.
- Общий тайм-аут лучше контролировать через `curl` (`--max-time` и повторные попытки), а не внешним Python-тайм-аутом. Иными словами, важны именно ограничения самого `curl` и его механизм повторных попыток.
- Если выбирается другой клиент, сначала нужно убедиться, что он стабильно получает ответ по HTTP/1.1 + TLS 1.2, и только потом вешать парсер.

## Ограничения

- Для одного адреса может быть несколько строк из-за названия здания, поэтому не стоит автоматически брать первую.
- Если результатов слишком много, нужно добавить в запрос город или район.
- Это навык только для чтения, значит адресные данные не нужно хранить.
