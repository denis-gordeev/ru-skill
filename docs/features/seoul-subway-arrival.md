# Руководство по прибытию поездов сеульского метро

## Что делает навык

- Получать время прибытия поездов по станции в реальном времени.
- Показывать направление движения и тип линии.
- Возвращать первое и второе сообщения о прибытии.

## Граничное примечание

Этот навык уже документно закрыт как `устаревший без развития`: прямая российская замена не подтверждена, а доступные публичные источники данных метро дают только низкоценные статические справочники вместо сопоставимого программного интерфейса реального времени. Навык сохраняется ради совместимости и не открывает новый перечень задач целевой линейки.

## Предварительные условия

- Прочитать [общую настройку](../setup.md)
- Прочитать [политику по секретам](../security-and-secrets.md)
- Получить ключ API Seoul Open Data Plaza

## Нужные переменные окружения

- `SEOUL_OPEN_API_KEY`

### Порядок разрешения учётных данных

1. Если переменная уже есть в окружении, использовать её.
2. Если агент работает через отдельное хранилище секретов, можно подтянуть ключ оттуда.
3. Если переменных окружения нет, сначала искать `SEOUL_OPEN_API_KEY` в `~/.config/ru-skill/secrets.env`, затем в `~/.config/k-skill/secrets.env`.
4. Если ни одного источника нет, запросить ключ у пользователя и сохранить его в хранилище секретов или `secrets.env`.

## Входные данные

- Название станции
- Необязательно: число записей в ответе

## Рабочий процесс

1. Если `SEOUL_OPEN_API_KEY` не задан, получить его по описанному порядку разрешения.
2. Запросить данные в реальном времени по станции.
3. Свести линию, направление, сообщения о прибытии и момент обновления.

## Пример

```bash
curl -s "http://swopenAPI.seoul.go.kr/api/subway/${SEOUL_OPEN_API_KEY}/json/realtimeStationArrival/0/8/강남"
```

## Ограничения

- Данные поступают в реальном времени и могут меняться каждые несколько секунд.
- Если написание станции отличается от ожидаемого программного интерфейса, ответ может быть пустым.
- Возможны суточные лимиты и квоты.
