# Руководство по `k-skill-proxy`

`k-skill-proxy` - это прокси на Fastify для бесплатных и публичных API, который сохраняется в `ru-skill` как базовая серверная заготовка для новых русскоязычных сценариев.

## Граничное примечание

Этот прокси остаётся переходным слоем, а не отдельным пользовательским целевым навыком. Его стоит поднимать только под конкретные бесплатные публичные сценарии API; само наличие `k-skill-proxy` в репозитории не означает, что устаревший AirKorea-поток или другие корейские источники снова становятся направлением развития `ru-skill`.

Сейчас в коде уже реализован устаревший модуль-посредник для AirKorea и сводка по мелкой пыли. Это не основной будущий фокус репозитория, но хороший пример того, как в проекте должен выглядеть безопасный прокси только для чтения.

## Для чего нужен прокси

- Хранить ключ вышестоящего API только на стороне сервера
- Сужать наружный интерфейс до разрешённых маршрутов
- Давать одну стабильную конечную точку для навыков и агентов
- Добавлять кэширование, ограничение частоты запросов и минимальную нормализацию ответа

Базовая схема остаётся такой:

```text
client/skill → k-skill-proxy → вышестоящий публичный API
```

## Текущие конечные точки

- `GET /health`
- `GET /v1/fine-dust/report`
- `GET /B552584/:service/:operation`

Последний маршрут ограничен набором разрешённых AirKorea операций и нужен только для устаревших сценариев.

## Рекомендуемые переменные окружения

На стороне клиента:

- `KSKILL_PROXY_BASE_URL=https://k-skill-proxy.nomadamas.org`

На стороне сервера:

- `AIR_KOREA_OPEN_API_KEY=...`
- `KSKILL_PROXY_HOST=127.0.0.1`
- `KSKILL_PROXY_PORT=4020`
- `KSKILL_PROXY_CACHE_TTL_MS=300000`
- `KSKILL_PROXY_RATE_LIMIT_WINDOW_MS=60000`
- `KSKILL_PROXY_RATE_LIMIT_MAX=60`

## Политика по безопасности и доступу

- Прокси в этом репозитории предназначен только для бесплатных API.
- Базовый режим: публичную конечную точку только для чтения без авторизации прокси.
- Безопасность достигается не авторизацией "на всякий случай", а узким разрешённым интерфейсом, кэшем и ограничением частоты запросов.
- Если появится злоупотребление или операционные проблемы, ограничения можно усилить отдельным изменением.

## Локальный запуск

```bash
node packages/k-skill-proxy/src/server.js
```

Перед запуском нужно экспортировать переменные окружения вручную или загрузить их из своего локального секрета.

## Развёртывание через PM2

В репозитории уже подготовлены:

- `ecosystem.config.cjs`
- `scripts/run-k-skill-proxy.sh`

Типовой порядок:

1. `pm2 start ecosystem.config.cjs`
2. `pm2 save`
3. `pm2 startup`
4. Привязать внешний входной прокси или туннель к `http://localhost:4020`

## Как использовать существующую устаревшую конечную точку

Сводка по мелкой пыли:

```bash
curl -fsS --get 'https://k-skill-proxy.nomadamas.org/v1/fine-dust/report' \
  --data-urlencode 'regionHint=서울 강남구'
```

Сквозной маршрут AirKorea:

```bash
curl -fsS --get 'https://k-skill-proxy.nomadamas.org/B552584/ArpltnInforInqireSvc/getMsrstnAcctoRltmMesureDnsty' \
  --data-urlencode 'returnType=json' \
  --data-urlencode 'numOfRows=1' \
  --data-urlencode 'pageNo=1' \
  --data-urlencode 'stationName=강남구' \
  --data-urlencode 'dataTerm=DAILY' \
  --data-urlencode 'ver=1.4'
```

## Как использовать прокси в новых русскоязычных сценариях

- Добавлять только публичные и бесплатные вышестоящие источники.
- Сначала фиксировать источник и ограничения в [docs/sources.md](/Users/denis/programming/autowork/ru-skill/docs/sources.md).
- Затем добавлять узкую конечную точку вместо общего универсального сквозного маршрута, если это возможно.
- По умолчанию нормализовать ответы на русском там, где это улучшает удобство использования и не скрывает важные поля вышестоящего API.

## Ограничения текущей реализации

- Прокси ещё завязан на устаревшее название `k-skill-proxy`.
- Единственный полностью реализованный вышестоящий источник сейчас - AirKorea.
- Русскоязычные прокси-модули-посредники пока не добавлены и остаются задачей следующих раундов разработки.
- Устаревшая конечная точка `k-skill-proxy.nomadamas.org` сохраняется ради совместимости, но не должен выглядеть как основной пользовательский вход в новые целевые сценарии.
