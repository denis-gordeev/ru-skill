# Замены навыков бронирования

Этот документ фиксирует исследование по замене устаревших навыков `srt-booking` и `ktx-booking` на российский сценарий.

Статус исследования: 2026-04-29.

## Что уже подтверждено

- Официальный пользовательский поток у РЖД существует, но он завязан на полноценное оформление заказа, пользовательский аккаунт и платёжный сценарий.
- `tutu.ru` и Яндекс Путешествия дают сильный пользовательский сценарий поиска и покупки ЖД-билетов, но в открытых материалах не подтверждён свободный публичный API для стабильной агентной автоматизации покупки.
- Уже реализованный `yandex-rasp` закрывает значимую часть задачи только для чтения: станции, расписания и поиск маршрутов без логина и без ненадёжной браузерной автоматизации.

## Матрица решений

| Кандидат | Тип поверхности | Официальность | Что можно подтвердить публично | Основные ограничения | Решение |
| --- | --- | --- | --- | --- | --- |
| `rzd-booking` | Официальное веб-оформление заказа | Да | У РЖД есть официальный пользовательский поток покупки билетов | Нужны аккаунт, платёжный поток и устойчивость к изменениям поверхностей оформления заказа; свободный публичный API для агентного бронирования не подтверждён | Не брать в автоматизированный MVP |
| `tutu-ru` | Агрегаторное веб-оформление заказа | Нет | Есть сильный пользовательский сценарий поиска, выбора мест и покупки | Публичный веб-поток только для чтения есть, но свободный public API для автоматизации бронирования не подтверждён | Рассматривать только как кандидат только для чтения/перенаправления |
| `yandex-travel-trains` | Агрегаторное веб-оформление заказа | Нет | Есть пользовательский сценарий поиска и покупки ЖД-билетов | Партнёрский API Яндекса документирован для базы туристических данных, но не как свободный публичный API бронирования поездов для локального навыка | Рассматривать только как кандидат только для чтения/перенаправления |
| `yandex-rasp` + перенаправление | Публичный API + внешний переход | Частично | Стабильный API только для чтения уже внедрён в репозиторий | Не покрывает выбор мест, оплату и жизненный цикл после бронирования | Текущий базовый путь для целевой линейки |

## Вывод по вехе

- Полноценную автоматизацию покупки российских ЖД-билетов нельзя считать хорошим следующим целевым навыком, пока не появится официальный и устойчивый программный интерфейс без антибот-обходов.
- Ближайший реалистичный вариант для миграции — не новый навык на запись, а аккуратный слой только для чтения/перенаправления поверх уже существующего `yandex-rasp` или поверх стабильных train-search страниц агрегаторов.
- Legacy `srt-booking` и `ktx-booking` сохраняются ради совместимости, но не должны становиться шаблоном для новых российских интеграций.

## Итог на 2026-04-29

- Отдельный навык-перенаправление для railway не открывается.
- `yandex-rasp` уже покрывает стабильную основу только для чтения: станции, расписания, маршруты и ориентиры по цене без логина и без автоматизации оформления заказа.
- Самостоятельный пакет-перенаправление сейчас дал бы только тонкую обёртку над внешними пользовательскими поверхностями оформления заказа РЖД, `tutu.ru` или Яндекс Путешествий, но не новую устойчивую API-функцию внутри репозитория.
- Поэтому замена для `srt-booking` и `ktx-booking` фиксируется как `yandex-rasp` для обнаружения + ручной переход пользователя во внешнее оформление заказа, без открытия нового `target`-пакета.

## Критерий закрытия Вехи 5

Веха 5 считается закрытой, если выполнено одно из двух условий:

1. Подтверждён официальный и устойчивый российский источник бронирования без логина, закрытых API и ненадёжных обходов антибота, после чего можно делать новый целевой пакет.
2. Зафиксировано, что такого источника нет, а репозиторий официально ограничивает замену для железнодорожного бронирования уровнем `обнаружение только для чтения + внешнее перенаправление`, не расширяя автоматизацию записи оплаты и бронирования.

Во втором случае перечень задач закрывается документно и регрессионно, без попытки искусственно дотянуть устаревшее бронирование до новой продуктовой линии.

На 2026-04-29 Веха 5 закрыта вторым способом.
