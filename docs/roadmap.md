## Вехи миграции

### Веха 1. Русификация верхнего уровня

Цель: убрать смешение русских и корейских заголовков в корневой документации и сделать репозиторий понятным без знания устаревшего контекста.

- `TODO.md` ведётся как живой перечень задач для следующих раундов автоматизации.

Статус: завершён.

### Веха 2. Инвентарь устаревших пакетов и новое позиционирование

Цель: развести то, что остаётся ради обратной совместимости, и то, что считается целевым развитием `ru-skill`.

Критерии готовности:

- Для каждого пакета рабочего пространства определён статус: `устаревший`, `переходный` или `целевой`.
- Выявлены имена пакетов и навыков, которые нельзя быстро переименовать из-за совместимости, и задокументирован план их обвязки брендом `ru-skill`.
- README и дорожная карта явно показывают, какие пакеты не являются целевым продуктовым направлением.
- Инвентарь зафиксирован в `docs/brand-inventory.md`.

Статус: завершён.

### Веха 3. Первый русскоязычный навык

Цель: добавить новый сценарий поверх публичного программного интерфейса или официального веб-интерфейса, не завязанный на корейские сервисы.

Критерии готовности:

- Есть выбранный источник в `docs/sources.md`.
- Есть рабочий навык/пакет или документированный сценарий только навыка.
- Есть README/руководство по функции, тесты или проверка на основе эталонных данных.
- Навык можно установить из репозитория по той же схеме, что и текущие навыки.

Статус: завершён.

### Веха 4. Управляемое сворачивание устаревших пакетов пакетов

Цель: сократить долю устаревших функций в публичной коммуникации, не ломая существующие потоки.

Критерии готовности:

- Для каждого устаревшего пакета решено: оставить как есть, вынести отдельно или заменить русскоязычным аналогом.
- Новые выпуски и документация не продвигают устаревшие пакеты как основной сценарий репозитория.
- Матрица замен поддерживается в дорожной карте и TODO.
- Все устаревшие SKILL.md файлы переведены на русский язык для единообразия документации.

Статус: завершён по документации и управлению миграцией. Устаревшие пакеты сохранены ради совместимости, но документно отделены от целевой линейки; незакрытые пробелы вынесены в следующую веху.

### Веха 5. Замены бронирования и гигиена выпусков

Цель: не просто держать устаревшие навыки бронирования как исторический хвост, а либо найти жизнеспособные российские замены, либо явно зафиксировать, что замена невозможна без проверки подлинности и закрытых программных интерфейсов.

Критерии готовности:

- Исследованы минимум два кандидата для замены `srt-booking` и `ktx-booking`: официальный РЖД поток и один агрегаторный сценарий только для чтения.
- В дорожной карте и TODO нет устаревших статусов round-summary, которые противоречат фактическому состоянию репозитория.
- Перечень выпускных задач и файлов changeset приведён в состояние, из которого можно делать следующий раунд публикации без ручной археологии по старым сводкам.

Статус: завершён; подзадача гигиены выпусков закрыта, исследование по заменам бронирования проведено документно, устаревшие железнодорожные документы выровнены с границей замен, а отдельный только для чтения/перенаправление навык сверх `yandex-rasp` признан нецелесообразным.

Текущее решение по направлению:

- Полноценный `rzd-booking` не идёт в минимальный рабочий вариант (MVP), пока не подтверждён устойчивый официальный интерфейс без автоматизации оформления заказа, входа и ненадёжных обходов защиты от роботов.
- `tutu.ru` и Яндекс Путешествия фиксируются как кандидаты на только для чтения/перенаправление сценарий, а не как подтверждённый публичный программный интерфейс бронирования.
- Базовый поиск железнодорожных маршрутов сценарий уже покрывается `yandex-rasp`; отдельный целевой пакет не открывается, пока он не добавляет устойчивую функцию программного интерфейса, а не тонкую обёртку над внешним оформлением заказа.
- Критерий закрытия вехи вынесен в [отдельный документ по заменам бронирования](booking-replacements.md).
