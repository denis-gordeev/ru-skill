# Источники

Этот документ фиксирует внешние интерфейсы, на которые уже опирается `ru-skill`, и источники, которые рассматриваются как база для русскоязычной миграции.

## Что здесь важно

- Основная цель репозитория сейчас: постепенно уходить от корейско-специфичных сценариев к российским и русскоязычным.
- Устаревшие источники ниже сохраняются, чтобы не ломать уже существующие навыки и тесты.
- Для новых функций предпочтение отдаётся бесплатным, публичным и официальным интерфейсам с понятными условиями использования.

## Первый выбранный русскоязычный источник

### Банк России: официальные курсы валют

- Страница с описанием сервисов XML Банка России: https://www.cbr.ru/development/SXML/
- Ежедневные курсы валют XML: https://www.cbr.ru/scripts/XML_daily.asp
- Динамика курса по валюте: https://www.cbr.ru/scripts/XML_dynamic.asp

Почему этот источник выбран первым:

- Это официальный источник Банка России, а не сторонний агрегатор.
- Доступ только для чтения и публичный, без входа и без пользовательских секретов.
- Минимальный сценарий полезен сам по себе: курс на сегодня, курс на дату, краткая динамика.
- Для первого нового навыка не нужен посредник или обход нестабильного веб-интерфейса.

Минимальная область действия первого навыка:

- Вход: код валюты (`USD`, `EUR`, `CNY`) и необязательная дата.
- Выход: номинал, курс ЦБ РФ, дата публикации, изменение к предыдущему доступному значению.
- Техническая основа: навык + небольшой пакет только для чтения с на основе эталонных данных тестом на нормализацию XML.
- Рабочее имя-кандидат: `cbr-rates` или `bank-of-russia-rates`.

Что не входит в первую область действия:

- Конвертация по пользовательским банковским курсам.
- Исторические графики и длинная аналитика.
- Любые операции записи, авторизация или пользовательские кабинеты.

## Второй выбранный русскоязычный источник

### Московская биржа: ISS API по акциям

- Страница ISS API: https://www.moex.com/a8531
- Публичная конечная точка по тикеру акции: https://iss.moex.com/iss/engines/stock/markets/shares/boards/TQBR/securities/SBER.json
- Публичный список акций на основной доске: https://iss.moex.com/iss/engines/stock/markets/shares/boards/TQBR/securities.json

Почему этот источник выбран следующим:

- Это официальный публичный интерфейс Московской биржи, а не сторонняя программа разбора котировок.
- Сценарий остаётся только для чтения и не требует входа, маркеров доступа или посредника.
- Источник хорошо дополняет `cbr-rates`: один пакет покрывает официальные курсы ЦБ РФ, второй - публичный рынок акций MOEX.
- Для минимального рабочего варианта достаточно двух стабильных чтений: карточка тикера и список инструментов.

Минимальная область действия второго навыка:

- Вход: тикер MOEX (`SBER`, `GAZP`, `LKOH`) и необязательный `board`, по умолчанию `TQBR`.
- Выход: `shortName`, `ISIN`, `lotSize`, предыдущая цена, задержанный `lastPrice`, изменение и время обновления.
- Дополнительно: первая страница тикеров для основной доски без секретов.
- Техническая основа: навык + пакет только для чтения + на основе эталонных данных тесты на нормализацию JSON ISS.

Что не входит во вторую область действия:

- Подписки в реальном времени, веб-сокеты и торговые операции.
- Облигации, валютный рынок, фьючерсы и опционы.
- Пользовательские портфели, брокерские кабинеты и авторизация.

## Третий выбранный русскоязычный источник

### Postcalc: справочник индексов и отделений Почты России

- Главная страница базы населённых пунктов: https://postcalc.ru/cities
- Пример страницы населённого пункта с параметрами API (`citykey`, `regid`): https://postcalc.ru/cities/%D0%A1%D1%8B%D0%BA%D1%82%D1%8B%D0%B2%D0%BA%D0%B0%D1%80
- Пример страницы отделения по индексу: https://postcalc.ru/offices/109189
- Описание параметров API на страницах базы: https://postcalc.ru/cities/Slavgorod%2C_22

Почему этот источник выбран третьим:

- Это российский источник только для чтения вне финансового домена.
- Интерфейс полезен сам по себе: можно получать индекс по населённому пункту и карточку отделения по известному индексу.
- Источник явно ссылается на эталонный справочник почтовых индексов объектов почтовой связи Почты России и дополнен открытыми геоданными.
- Для минимального рабочего варианта не нужен вход, пользовательские секреты, посредник или операции записи.
 
Минимальная область действия третьего навыка:

- Вход: почтовый индекс или `citykey` населённого пункта.
- Выход для индекса: название отделения, адрес, тип ОПС, регион, координаты и ссылка на карточку.
- Выход для населённого пункта: `citykey`, `regid`, индекс по умолчанию и список доступных отделений.
- Техническая основа: навык + пакет только для чтения + на основе эталонных данных тесты на нормализацию HTML страниц `cities` и `offices`.
- Выбранное имя пакета: `postcalc-postcodes`.

Что не входит в третью область действия:

- Расчёт стоимости отправлений и любые сценарии на запись.
- Полноценный нечёткий поиск по произвольной строке, если он потребует нестабильного автодополнения на JS.
- Отслеживание посылок и интеграции с личным кабинетом Почты России.

## Четвёртый выбранный русскоязычный источник

### hh.ru: публичный API вакансий и регионов

- Публичная документация API: https://api.hh.ru/openapi/redoc
- Поиск вакансий: https://api.hh.ru/vacancies
- Карточка вакансии: https://api.hh.ru/vacancies/131927189
- Поиск региона: https://api.hh.ru/areas/1

Почему этот источник выбран четвёртым:

- Это русскоязычный сценарий вне финансов и логистики, полезный сам по себе.
- Публичный API только для чтения доступен без пользовательской авторизации для поисковых сценариев.
- Источник добавляет в целевую линейку отдельный вертикальный домен: рынок труда и вакансии.
- Для минимального рабочего варианта достаточно трёх стабильных чтений: поиск региона, поиск вакансий и карточка вакансии.

Минимальная область действия четвёртого навыка:

- Вход: поисковая строка вакансии, необязательный `areaId`, либо конкретный `vacancyId`.
- Выход для поиска: список вакансий с `title`, `salary`, `employer`, `experience`, `workFormats` и `vacancyUrl`.
- Выход для карточки: `descriptionText`, адрес, ближайшее метро, режим занятости и режим работы.
- Дополнительно: поиск региона по `areaId`, чтобы можно было явно связывать поиск с Москвой, Санкт-Петербургом и другими регионами.
- Техническая основа: навык + пакет только для чтения + на основе эталонных данных тесты JSON.
- Выбранное имя пакета: `hh-vacancies`.

Что не входит в четвёртую область действия:

- Отклики, избранное, личный кабинет и любые операции записи.
- Авторизованные сценарии работодателя или соискателя.
- Полный охват всех словарей HH API, если они не нужны для базового поиска и чтения карточки.

Что не входит в шестую область действия:

## Седьмой выбранный русскоязычный источник

### МЧС России: региональные страницы экстренных предупреждений

- Пример индекса предупреждений: https://46.mchs.gov.ru/deyatelnost/press-centr/operativnaya-informaciya/shtormovye-i-ekstrennye-preduprezhdeniya
- Пример карточки предупреждения: https://46.mchs.gov.ru/deyatelnost/press-centr/operativnaya-informaciya/shtormovye-i-ekstrennye-preduprezhdeniya/5695266
- Корневой федеральный сайт: https://mchs.gov.ru/

Почему этот источник выбран седьмым:

- Это официальный российский источник по публичной безопасности, а не агрегатор новостей или погоды.
- доступ только для чтения к региональным страницам не требует авторизации, маркеров доступа и пользовательских секретов.
- Источник добавляет в целевую линейку отдельный домен: экстренные предупреждения и погодные риски.
- Минимальный рабочий вариант можно собрать на устойчивых интерфейсах HTML списка предупреждений и карточки предупреждения.

Минимальная область действия седьмого навыка:

- Вход: `regionHost`, например `46`, `78` или `moscow`, и необязательный `warningId`.
- Выход для списка: `title`, `publishedAt`, `publishedAtIso`, `tag`, `warningId`, `url`.
- Выход для карточки: `title`, `bodyText`, дата публикации и ссылки для экспорта `pdfUrl`/`wordUrl`, если они доступны на странице.
- Техническая основа: навык + пакет только для чтения + на основе эталонных данных тесты HTML для списка предупреждений и одной карточки.
- Выбранное имя пакета: `mchs-storm-warnings`.

Что не входит в седьмую область действия:

- Поиск региона по естественному языку, если для этого потребуется отдельный справочник региональных имён узлов.

### Отложенные кандидаты

#### Маркетплейсы (Wildberries/Ozon/Price.ru/E-katalog)

- Wildberries API требует маркер продавца (dev.wildberries.ru), а публичная выдача быстро уходит в поток с защитой от ботов.
- Ozon Seller API также требует авторизацию, а публичная выдача отвечает проверкой на ботов.
- Price.ru и E-katalog остаются резервными кандидатами, если текущий интерфейс с серверной отрисовкой (SSR) Яндекс Маркета перестанет быть доступной.
- **Решение**: основная замена для `daiso-product-search` уже закрыта через `yandex-market-search`; резервный запасной вариант держать на случай деградации страниц с серверной отрисовкой (SSR) Маркета.

#### Поиск ближайших (2GIS/Яндекс.Карты/Zoon)

- 2GIS Catalog API требует ключ API (docs.2gis.com).
- Яндекс.Карты Geosearch API требует ключ API.
- Zoon.ru — публичный справочник организаций, страницы с серверной отрисовкой (SSR), без защиты от ботов, без ключей API.
- **Решение**: реализован `osm-nearby` через Overpass API как основной бесплатный источник без ключа API; реализован `zoon-nearby` как дополнительный источник с рейтингами, телефонами и режимами работы; 2GIS/Яндекс.Карты остаются опцией для промышленного использования.

### Бытовые и городские данные

- Официальные погодные и климатические API с публичным доступом или бесплатным тарифом
- Источники по качеству воздуха и предупреждениям, пригодные для посредника только для чтения
- Официальные или общедоступные источники по адресам и индексам
- Официальные расписания транспорта и железнодорожные веб-интерфейсы, допускающие аккуратный доступ только для чтения

### Электронная коммерция и геопоиск

- Публичные карточки магазинов и поисковые страницы торговых площадок
- Официальные страницы магазинов с адресами, режимом работы и контактами
- Каталоги товаров и страницы наличия, которые можно использовать без приватных API и без входа

### Финансы и гос-сценарии

- веб-интерфейсы только для чтения с официальной документацией или стабильным удобством использования
- Пошаговые официальные инструкции, которые можно превращать в руководства по навыкам без хранения чувствительных данных

## Правила отбора новых источников

- Берём только то, что можно использовать легально и без обхода платных ограничений.
- Для интерфейсов посредника приоритет у бесплатных API и официальных открытых данных.
- Если источник требует секрет, этот секрет должен жить только на серверной стороне или в локальном окружении пользователя.
- Если источник нестабилен, в репозиторий добавляется эталонный набор данных или явная документация о рисках.
