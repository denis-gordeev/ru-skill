# Релизы и автоматическая публикация

Этот репозиторий использует **файлы `.changeset` для npm** и **`release-please` для Python**.

## Пакеты Node.js / npm

- Расположение: `packages/*`
- Управление версиями: файлы `.changeset`
- Процесс публикации: `.github/workflows/release-npm.yml`
- Момент публикации: после слияния сгенерированного ботом запроса на слияние `Version Packages` в `main`
- Предпочтительный способ аутентификации: доверенная публикация через GitHub OIDC
- Базовое правило: версии пакетов не редактируются вручную для релиза, вместо этого в запрос на слияние добавляется `.changeset/*.md`

### Поток релиза

1. В функциональном запросе на слияние добавляется `.changeset/*.md`.
2. Запрос на слияние вливается в `main`.
3. Автоматизация `.changeset` создаёт запрос на слияние `Version Packages`.
4. Запрос на слияние `Version Packages` вливается в `main`.
5. GitHub Actions публикует только изменившиеся пакеты npm через `changeset publish`.
6. `CHANGELOG.md` в пакетах ведёт автоматизация `.changeset`, а отдельные GitHub Releases для пакетов npm не создаются, пока `createGithubReleases: false`.

## Доверенная публикация для npm

- Предпочтительна OIDC/доверенная публикация, а не долгоживущий `NPM_TOKEN`.
- Для этого процесс должен иметь `id-token: write`, а пакет на стороне npm должен быть настроен на доверенного издателя для этого репозитория.
- `NPM_CONFIG_PROVENANCE=true` остаётся включённым, чтобы npm публиковал метаданные происхождения.
- Если доверенная публикация недоступен для конкретного пакета или реестра, только тогда допустим запасной вариант на токен. Такой запасной вариант нужно отдельно задокументировать и обосновать.

## Пакеты Python

- Расположение: `python-packages/*`
- Управление версиями: `release-please`
- Процесс публикации: `.github/workflows/release-python.yml`
- Момент публикации: только если `release-please` сообщил `release_created=true` для реального пути пакета
- Текущее состояние: в репозитории пока нет реального пакета Python, поэтому процесс остаётся только каркасной заготовкой

## Проверка перед релизными изменениями

```bash
npm install
npm run ci
```

Если меняются релиз/процесс/метаданные пакета, нужно обязательно прогонять `npm run ci` и держать документацию, процесс и метаданные в одном изменении.
