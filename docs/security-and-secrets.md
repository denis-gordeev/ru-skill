# Политика секретов

`ru-skill` объявляет только имена нужных переменных окружения. Способ поставки самих значений остаётся за агентом и пользовательской средой.

## Порядок разрешения учётных данных

Все навыки, которым нужны секреты, используют один и тот же приоритет.

1. Если значение уже задано в окружении, оно используется напрямую.
2. Если агент умеет работать со своим хранилищем секретов, например `1Password CLI`, `Bitwarden CLI` или Связка ключей macOS, он может взять значение оттуда и передать в окружение.
3. Если хранилища секретов нет, сначала используется `~/.config/ru-skill/secrets.env`, а при его отсутствии допускается устаревший резерв `~/.config/k-skill/secrets.env`; оба файла должны быть в формате dotenv с правами `0600`.
4. Если секрета нет ни в одном месте, агент должен запросить его у пользователя и сохранить через вариант 2 или 3.

Хранение в стандартном пути является резервным механизмом, а не обязательным требованием.

## Стандартный файл секретов

- Предпочтительный путь: `~/.config/ru-skill/secrets.env`
- Устаревший резерв: `~/.config/k-skill/secrets.env`
- Явное переопределение: `RU_SKILL_SECRETS_FILE`, затем `KSKILL_SECRETS_FILE`
- Формат: простой dotenv (`KEY=value`, одна переменная на строку)
- Права: `0600` (только владелец может читать и писать)

```dotenv
KSKILL_SRT_ID=replace-me
KSKILL_SRT_PASSWORD=replace-me
KSKILL_KTX_ID=replace-me
KSKILL_KTX_PASSWORD=replace-me
SEOUL_OPEN_API_KEY=replace-me
AIR_KOREA_OPEN_API_KEY=replace-me
```

`KSKILL_PROXY_BASE_URL` специально не включён в минимальный шаблон секретов выше: это не секрет, а необязательное переопределение опубликованного совместимого посредника. Если оно действительно нужно, его можно хранить рядом с остальными значениями в том же файле dotenv или задавать отдельно через окружение:

```dotenv
# Необязательное переопределение адреса для fine-dust-location
KSKILL_PROXY_BASE_URL=https://k-skill-proxy.nomadamas.org
```

## Политика при отсутствии секрета

Если у навыка с проверкой подлинности не хватает значения, агент не должен обходить это сторонними сервисами или неофициальными трюками.

- Пользователю нужно точно назвать отсутствующую переменную окружения.
- Получение значения должно идти по порядку разрешения учётных данных.
- Нельзя автоматически подставлять альтернативные сайты, неофициальные программные интерфейсы или жёстко заданные значения.
- Отсутствие секрета не является причиной молча переключаться на другой сервис.

## Запрещённые практики

- Хранить в git файл с настоящими секретами.
- Писать в документации реальные пароли даже как пример.
- Автоматически включать неофициальные обходы только потому, что секрета нет.

## Упрощённая модель угроз

- `~/.config/ru-skill/secrets.env` остаётся обычным файлом dotenv.
- Устаревший файл `~/.config/k-skill/secrets.env` пока тоже считается допустимым, потому что нужен для совместимости.
- Права `0600` защищают эти файлы от других пользователей той же машины.
- `.gitignore` нужен, чтобы файл не утёк в git.
- Агент может читать и писать этот файл, и это ожидаемое поведение.
- В среде OpenClaw/агентов предполагается, что пользователь осознанно делегирует агенту работу с учётными данными.

## Стандартные имена переменных

- `KSKILL_SRT_ID`
- `KSKILL_SRT_PASSWORD`
- `KSKILL_KTX_ID`
- `KSKILL_KTX_PASSWORD`
- `SEOUL_OPEN_API_KEY`
- `AIR_KOREA_OPEN_API_KEY`
- `KSKILL_PROXY_BASE_URL`

Для `fine-dust-location` переменная `KSKILL_PROXY_BASE_URL` не считается секретом сама по себе: это только необязательное переопределение опубликованной конечной точки посредника. Секретным значением в этом сценарии остаётся `AIR_KOREA_OPEN_API_KEY`, если используется прямой резервный доступ или посредник на собственном сервере.

Все навыки этого репозитория, которым нужны учётные данные, опираются на эту политику. Общий порядок настройки описан в [руководстве по настройке](setup.md).
