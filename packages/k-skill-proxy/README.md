# k-skill-proxy

`k-skill-proxy` - сервер-посредник на Fastify для бесплатных и публичных программных интерфейсов, который пока используется как базовый серверный слой во время миграции `ru-skill` на российские и русскоязычные сценарии.

Сейчас пакет в основном обслуживает устаревший сценарий с AirKorea и мелкой пылью, но его архитектура рассчитана на добавление других модулей-посредников только для чтения с узким разрешённым интерфейсом.

## Граничное примечание

Этот пакет остаётся переходной инфраструктурой и слоем совместимости, а не отдельным пользовательским целевым продуктом. Устаревшая конечная точка и имя `k-skill-proxy` сохраняются ради совместимости; это не означает, что AirKorea/`fine-dust` снова становятся основным направлением развития `ru-skill`.

## Текущие адреса

- `GET /health`
- `GET /v1/fine-dust/report`
- `GET /B552584/:service/:operation`

`/B552584/:service/:operation` ограничен набором разрешённых AirKorea маршрутов и не является общим произвольным посредничеством.

## Переменные окружения

- `AIR_KOREA_OPEN_API_KEY` - ключ вышестоящего программного интерфейса для AirKorea на стороне сервера
- `KSKILL_PROXY_HOST` - по умолчанию `127.0.0.1`
- `KSKILL_PROXY_PORT` - по умолчанию `4020`
- `KSKILL_PROXY_CACHE_TTL_MS` - по умолчанию `300000`
- `KSKILL_PROXY_RATE_LIMIT_WINDOW_MS` - по умолчанию `60000`
- `KSKILL_PROXY_RATE_LIMIT_MAX` - по умолчанию `60`
- `KSKILL_PROXY_NAME` - имя сервиса для `/health`, по умолчанию `k-skill-proxy`

Базовая политика пакета: посредник для бесплатных программных интерфейсов по умолчанию остаётся публичным и без проверки подлинности, но с узким списком маршрутов, буфером и ограничением частоты запросов.

## Локальный запуск

```bash
node packages/k-skill-proxy/src/server.js
```

Перед запуском нужно подготовить переменные окружения, включая `AIR_KOREA_OPEN_API_KEY`, если нужен устаревший сценарий `fine-dust`.

Если использовать репозиторный вспомогательный скрипт `scripts/run-k-skill-proxy.sh`, порядок разрешения будет таким:

1. `RU_SKILL_SECRETS_FILE`
2. `KSKILL_SECRETS_FILE`
3. `~/.config/ru-skill/secrets.env`
4. `~/.config/k-skill/secrets.env`

То есть путь с приоритетом `ru-skill` считается основным, а устаревший файл остаётся только резервным механизмом.

## Операционная модель

- ключи вышестоящих программных интерфейсов не выдаются клиенту
- клиент обращается только к посреднику
- новые вышестоящие источники добавляются как узкие модули-посредники для бесплатных программных интерфейсов
- приоритет у адресов только для чтения с понятным источником данных

## Развёртывание

Для фонового запуска в репозитории используются `ecosystem.config.cjs` и `scripts/run-k-skill-proxy.sh`.
